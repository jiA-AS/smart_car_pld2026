# 绿光白天准确识别修改包说明（green_detect V4.1）

> 适用仓库：`jiA-AS/smart_car_pld2026`（"新代码"基线）
> 场景：**靶标 = 人手持的 8×8 绿色 LED 点阵灯**，小车双目识别后自动跟随（s2 拨杆 Match 档，tracker_ctrl 链路现成）
> 解决问题：白天识别误识别严重，导致跟随乱走/乱停
> ⚠️ 上一版交付中的 ESP 端文件（led8x8、下行 V1.3、fishbot 集成）系误解靶标位置，**已全部作废删除，ESP32 固件不需要任何改动**。

---

## 一、白天误识别的根因

旧判决（green_detect V3）只有一个颜色条件：

```
is_green = (G ≥ th_g) && (R ≤ th_rb) && (B ≤ th_rb)     // 白天档 G≥40, R/B≤12
```

白天失效的四个机制：

| # | 根因 | 典型误识别源 |
|---|---|---|
| 1 | "R/B≤12"在自动白平衡下压不住绿植——OV5640 白天 AWB 会把绿色场景的 R/B 压到 12 以下 | 整片绿植、草地直接通过 |
| 2 | 只有面积下限（MIN_AREA=100）**没有上限** | 绿植 cnt 上万也照样 found |
| 3 | 没有形状约束 | 稀疏枝叶、绿色纹理、长条绿物 |
| 4 | 单帧即输出 | 玻璃/水面/金属的瞬态绿反光 |

误识别直接喂给 tracker_ctrl：false found → 小车朝错误目标转向/前进，表现为"乱跟"。

## 二、修改策略：五道闸（green_detect V4.1）

针对"手持 8×8 正方形主动发光点阵"这个靶标特征逐层收紧：

### 闸 1：差分颜色判决（核心）
```
is_green = (G ≥ th_g) && (G-R ≥ th_diff) && (G-B ≥ th_diff)
```
8×8 点阵是**主动发光饱和绿**，G-R/G-B 差 ≥20；白天绿植是反射光"浑浊绿"，差值小。差分对曝光/白平衡漂移天然鲁棒（整体亮度变、差值不变），比旧的"R/B 绝对上限"更适合白天。白天档 `th_diff=16`，调试档 10。

### 闸 2：面积窗 `MIN_AREA ≤ cnt ≤ MAX_AREA`
新增 MAX_AREA=6000（画面的 ~6%）：整片绿植/绿牌/绿衣直接排除。8×8 点阵物理尺寸固定，cnt 与跟随距离一一对应——现场用调试档 OSD 的 `G1/G2` 行读 cnt 标定：**最近跟随距离的 cnt×1.5 定 MAX_AREA，最远距离的 cnt×0.7 定 MIN_AREA**（top 例化现 MIN=100）。

### 闸 3：密度判决 `cnt×8 ≥ bbox宽×bbox高`
实心发光点阵填充率 50%+；稀疏枝叶/绿纹理 <10%（阈值 12.5%）。纯移位比较，零除法零帧存。

### 闸 4：多帧确认 `CONFIRM=2`
raw_ok 连续 2 帧才输出，丢 1 帧即清；30fps 下延迟仅 ~67ms，瞬态反光滤除。
★ **注意**：若手持灯是扫描式驱动（MAX7219 类）且实测 found 闪烁——相机曝光与灯扫描拍频所致，把 `CONFIRM` 改 1 或提高灯的扫描频率（WS2812 恒定亮无此问题）。

### 闸 5：方形度判决（V4.1 新增，针对点阵形状）
```
bbox_w ≤ 2×bbox_h 且 bbox_h ≤ 2×bbox_w     // 长宽比 0.5~2.0
```
8×8 点阵是正方形，手持旋转/透视投影下仍接近 1:1；**长条绿物（竹竿、绿边线、门缝反光条）长宽比悬殊直接排除**。可用 `SQUARE_EN=0` 关闭。

|---|---|---|---|---|---|---|

## 四、跟随功能确认（现成链路，无需改）

跟随控制链路已在你仓库里：green_detect×2 → 顶层融合 → tracker_ctrl V4（三模式）→ V1.1 下行 → ESP 电机：

| 识别状态 | tracker 行为 |
|---|---|
| 双目都看到 | S_MATCH：双目测距 dist_mm 距离环，dist≤300mm 判定到达停车 |
| 仅一路看到 | S_MONO：方位追踪+偏移补偿，低速 25% 前进 |
| 都看不到 | S_STOP：原地停车（不转圈） |

使用：s2 右拨杆打到 **Match 档（下）**，手持 8×8 灯在镜头前移动，小车即跟随。识别做准之后这条链路自然就对了——本次误识别修复正是跟随稳定的前提。

## 五、上车验证清单

1. 替换 3 个文件，全量综合+实现+烧写（ESP 不动）。
2. 白天户外：镜头扫过绿植/草地/绿牌/绿边线 → s1 下档看 `G1/G2` cnt，背景应全被拦（found 不触发）；手持灯入镜 → 稳定 found。
3. 手持灯在画面内**左右平移/前后推拉/缓慢转动手腕**：质心应连续跟踪不丢（方形度冗余 2:1，正常手持旋转不会出界）。
4. s2 打 Match 档：灯左移小车左转、灯右移右转、灯远走小车前进、灯贴近（≤30cm）停车。
5. 用手遮挡灯再放开：遮挡即停车，放开 2 帧（~67ms）内恢复跟随。
6. 若远距离（>8m）灯丢失：先看调试档 cnt 是否低于 MIN_AREA=100，按第四节标定方法调面积窗；暗光可临时切 s1 下档用放宽阈值。

## 六、识别不了的排查决策树（按顺序试，每步看结果）

**第 0 步：s1 拨到调试档（下档）再试**
- 调试档能识别 → 颜色闸太紧：`NORM_TH_DIFF` 16→12，`NORM_TH_G` 40→32
- 调试档也不能 → 形状/面积闸问题，继续往下

**第 1 步：看调试档 OSD 的 `G1/G2` cnt 值**
| 现象 | 病灶 | 改法 |
|---|---|---|
| cnt = 0 恒零 | 颜色闸全拦 | `th_g`→28、`th_diff`→10；检查镜头是否对着灯 |
| cnt 有值但 < MIN_AREA | 面积下限拦 | top 例化 `MIN_AREA` 再降（已改 60，可试 40） |
| cnt 正常（64~几千）但 found 不触发 | 密度/方形度拦 | `DEN_SHIFT`→4（已改）；方形度临时 `SQUARE_EN=0` 验证 |
| found 时有时无闪烁 | 多帧确认/灯扫描拍频 | `CONFIRM`→1；扫描式灯提高扫描频率 |

**本次 V4.2 已按你的点阵特性预设**（top 两处例化 + green_detect 默认值同步）：
- `DEN_SHIFT` 3→4（密度 ≥6.25%）：点阵是 64 个分离亮点+暗间隙的稀疏结构，填充率仅 ~10~16%，12.5% 阈值必拦
- `MIN_AREA` 100→60：远距离每个 LED 仅 1 像素时 cnt≈64

**放宽后误识别回潮怎么办**：零星小光点（cnt<50、bbox 大、密度<5%）在 6.25% 下仍被拦；若仍有回潮，`DEN_SHIFT` 回 3 同时 `MIN_AREA` 提到 150——用"点阵 cnt≈64×每灯像素数 vs 零星点 cnt<50"的规模差区分。

## 七、参数速查

| 参数 | 位置 | 默认 | 含义 |
|---|---|---|---|
| `NORM_TH_G / NORM_TH_DIFF` | mode_switch | 40 / 16 | 白天档：绿下限 / 差分下限 |
| `NIGHT_TH_G / NIGHT_TH_DIFF` | mode_switch | 28 / 10 | 调试档（夜间放宽） |
| `MIN_AREA / MAX_AREA` | green_detect | 30 / 6000 | 面积窗（top 例化 MIN=60 [V4.2]，按跟随距离标定） |
| `DEN_SHIFT` | green_detect | 4 [V4.2] | 密度阈值 = 1/2⁴ = 6.25%（点阵稀疏亮点结构） |
| `CONFIRM` | green_detect | 2 | 多帧确认（扫描式灯改 1） |
| `SQUARE_EN` | green_detect | 1 | 方形度判决开关（靶非标灯时关） |
