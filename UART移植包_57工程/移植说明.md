## 需要新顶层吗？——不需要

FPGA 工程永远只有一个顶层（`top_dual_ov5640_lcd`）。所谓"不同的链"不是多个顶层，
而是顶层之下的**子模块层次**：视频链已由 ddr3_top / lcd_rgb_top 等子模块收拢，
传感器链由 sensor_link 收拢，顶层只负责把它们并排例化、连到各自引脚。
这个结构就是最终形态，阶段 2/3 只是继续往这两个"链"内部加模块。

## 顶层相比原版的改动（就两处）

1. 端口表加了 `uart_rxd`（输入）和 `uart_txd`（输出）——**必须是端口，内部 wire 到不了芯片引脚**；
2. `endmodule` 前加了 `u_sensor_link` 例化；解码输出现阶段全部悬空 `()`，
   综合器会修剪（只有 unused 警告，无影响），阶段 2/3 再接线。

## XDC 追加（pin.xdc 末尾）

```tcl
set_property -dict {PACKAGE_PIN E13 IOSTANDARD LVCMOS33} [get_ports uart_rxd]
# 冒烟测试期：txd 指到 USB 串口 D17，电脑串口助手直接看 V1.1 帧
```

## 冒烟测试步骤（不接 ESP32 就能做一大半）

1. 6 个文件 Add 进 57 工程 + 替换顶层 + XDC → Generate Bitstream → 烧录；
2. **画面应照常**（视频链一行未动，若画面异常说明顶层改坏了，对照原版 diff）；
3. 电脑串口助手 115200 打开 USB 串口：应看到 50Hz 的 9 字节帧
   `55 AA 02 00 xx xx xx xx ??`（mode=0，left/right 是 enc0/timestamp 低 16 位，全 0 也正常——还没接 ESP32）；
4. 接 ESP32（GPIO42→J1 UART2_RXD，GND 共地）：转动车轮，帧里 left 字段（enc0 低 16 位）
   应跟着变化——**上行接收+解包+下行发送全链验证完毕**；
5. 一切正常后，把 uart_txd 约束改到 D16，接 ESP32 GPIO41，进入指南的阶段1收尾
   （ESP32 端 V1.1 解析器写好前，FPGA 发的是 mode=0 停车帧，安全）。

## 当前下行帧说明

sensor_link.v 里 `u_ctrl_tx` 的接线：`mode=8'd0`（停车）、`left=enc0[15:0]`、`right=timestamp`。
这是**冒烟测试专用接法**——阶段 3 接追踪控制时只需把这三个端口改接 `tracker_ctrl` 的输出。
